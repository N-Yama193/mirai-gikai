# 広川町議会フォーク ロードマップ

本リポジトリ（`N-Yama193/mirai-gikai`）は [team-mirai/mirai-gikai](https://github.com/team-mirai/mirai-gikai) のフォークで、国会法案向けのプラットフォームを **広川町議会向け** に作り替えることを目的としている。

このドキュメントは、これまで会話ベースで進めてきた作業を後から整理・文書化したものである。着手前に策定された計画書ではなく、**実装済みの内容と、その過程で確定した設計判断・先送り事項の記録**として扱うこと。

- 作成日: 2026-08-11（Phase 4 完了時点まで反映）

## 全体方針

- 広川町向けの新機能は `web/src/features/{assemblies,general-questions,agenda-items}` に**追加**する形で実装してきた。Phase 4 で定例会一覧をトップページ（`/`）へ統合し、`/gikai` は恒久リダイレクトのみを残している
- 既存の国会法案（`bills`）関連コード（約100ファイル）は**削除せず温存**している。扱いは未決（後述）
- データアクセスは `createAdminClient()`（service role）経由のサーバーサイドのみ。RLS はテーブルで有効化するがポリシーは定義しない（`AGENTS.md` の規約に準拠）

## 確定済みの設計判断

再検討の手戻りを防ぐため、これまでに合意した判断を記録しておく。

| 論点 | 判断 | 理由 |
|---|---|---|
| 旧 `agenda_summaries` / `question_topic_summaries` の扱い | **温存し、Phase 3-② とは別機能とする** | 旧テーブルは「本文自体をやさしく/詳しく書き換える」用途（国会版の `bill_contents.difficulty_level` 相当）。Phase 3-② の「論点＋結論の要約カード」とは目的が異なる |
| 一般質問の要約元テキスト | 配下の全 `question_topics.raw_excerpt` を連結して AI に渡す | `general_questions` 自体に本文カラムがないため。ハッシュも連結後の全体に対して計算する |
| admin 画面のスコープ | **一覧＋生成/公開/再生成ボタンのみ**。本文編集フォームは作らない | 本文の投入は当面 SQL 直接投入で運用する |
| AI 要約の生成方式 | Server Action 内で同期的に `await` する | 設計仕様書の `after()` による非同期化は「保存処理をブロックしない」ための設計。本フォークでは編集フォームがなく、生成の起点が管理画面のボタンのみのため過剰 |
| 公開済み要約の保護 | 自動再生成はしない。本文ハッシュ不一致時に admin 一覧へ警告バッジを出し、再生成は必ず人の操作を経る | `ai_summary` 列が1つのみで、下書きと公開版を同時に持てないため |
| 要約生成モデル | `AI_MODELS.claude_sonnet_5` | 住民向けの公開コンテンツのため品質重視 |
| `CHAT_ENABLED` の既定値 | **OFF**（`"true"` のときのみ有効） | 環境変数の設定漏れで意図しない LLM 課金が走るのを防ぐ fail-closed 設計 |
| カラーパレットの適用方法 | 既存トークン（`--primary` / `--color-mirai-*`）の**名前は変えず値だけ**差し替える | 名前を変えると `text-primary-accent` や `bg-mirai-gradient` を使う既存コンポーネントが旧テーマカラーのまま取り残されるため |
| 絣模様の実装 | 面はインライン SVG（`KasuriPattern`）、線は CSS ユーティリティ（`.kasuri-divider` / `.kasuri-edge`） | 線に SVG を使うと DOM 要素が無駄に増えるため用途で使い分ける。**不規則さに `Math.random()` は使わない**（SSR とクライアントで値がずれハイドレーション不一致を起こす） |
| favicon / OGP 画像 | `next/og` の `ImageResponse` でコードから動的生成する | 「画像素材を持ち込まない」方針を保ったまま FORK_GUIDELINES の差し替え要件を満たすため |
| `/gikai` の廃止方法 | インデックスのみ 308 リダイレクト。配下の議案・一般質問ルートは維持 | 子ルートまで URL を変えると影響範囲が大きく、既存リンクも切れるため |

## 未着手・先送り事項

### A. 公開に必要な必須作業（現状のブロッカー）

1. **Vercel プロジェクトの新規作成とデプロイ設定**
   - 現状、このフォークでは **GitHub Actions が一度も実行されていない**（フォークでは Actions が既定で無効のため）。`deploy.yml` が動いておらず、Vercel Deploy Hook も叩かれたことがない
   - リポジトリ内に `.vercel` フォルダは存在せず、`web/vercel.json` / `admin/vercel.json` にもアカウント情報は含まれない
   - GitHub サイドバーの `gikai.team-mir.ai` は **upstream（team-mirai）の本番サイト**。フォーク時に homepage フィールドごと引き継がれたもので、本リポジトリの所有ではない
   - 必要な手順: Vercel でプロジェクトを2つ作成（Root Directory を `web` / `admin`）→ 環境変数設定 → Deploy Hook 作成 → GitHub Secrets（`WEB_VERCEL_DEPLOY_HOOK_URL` / `ADMIN_VERCEL_DEPLOY_HOOK_URL`）登録 → Actions 有効化
   - 注意: `vercel.json` が `main` / `develop` の git 連携ビルドを無効化しているため、push だけではビルドされない（Deploy Hook 必須）

2. **利用規約・プライバシーポリシー等の法的文書の見直し**（Phase 4 で判明）
   - `web/src/app/(main)/{terms,privacy}/page.tsx` と `developers/` 配下の文書は、**政治団体「チームみらい」を運営主体として記述**したままになっている
   - Phase 4 ではサービス名の機械的な置換を**意図的に行っていない**。「チームみらいが運営する」と書かれた文書のサービス名だけを差し替えると、内容が事実と食い違う文書になってしまうため
   - 運営主体・問い合わせ先・データの取り扱いを含めた書き直しが必要で、法務判断を伴う。公開前の必須対応
   - なお FORK_GUIDELINES.md の必須要件（サービス名・ロゴ・カラー・免責文言）自体は Phase 4 で対応済み

### B. 広川町向け機能の未完成部分

- **AI 要約の実生成が未検証** — `AI_GATEWAY_API_KEY` 未設定のため、Claude API 経由の実生成は動作未確認（未設定時は `GatewayAuthenticationError` となり、ステータスは `none` のまま保持されるところまでは確認済み）
- **会議録 PDF（`minutes_documents`）の表示画面がない**
- **議員（`council_members`）の一覧・詳細ページがない**
- **本文の入力手段が SQL 直接投入のみ**
- **議案本文中の案内バナーが残る** — `LongPressSection`（「わからない言葉を選択すると AI に質問できます」）が markdown 埋め込みタグとして残存。チャット無効化後は案内だけが残り実際には機能しない。費用リスクはない

### C. 品質・運用

- **新機能のテストコードが未追加** — `assemblies` / `general-questions` / `agenda-items` に `.integration.test.ts` がない（既存の `diet-sessions` などが参考になる）
- **国会法案（`bills`）関連コードの扱いが未決** — 約100ファイルを温存中。削除するか残すかの方針が未定
- **`lint-staged` がリポジトリ全体を再フォーマットしていた（Phase 4 直後に修正済み）**
  - 設定が `"*.{js,jsx,ts,tsx}": "pnpm run lint:fix"`（= `biome format --write .`）となっており、末尾の `.` によってステージ対象に関わらずリポジトリ全体に適用されていた。コミットのたびに無関係な約1000ファイルが変更され、都度 revert が必要だった
  - **実害が出た**: Phase 4 のコミット時、biome の診断出力が上限で切り詰められ（`Diagnostics not shown: 113`）、画面に見えていたのは無関係な既存ファイルの警告だった。そのため本当のエラー（自分が追加した `opengraph-image.tsx` の `noArrayIndexKey` 2件）が隠れ、原因の切り分けに手戻りが発生した
  - 修正内容: `biome check --write --no-errors-on-unmatched` に変更し、lint-staged が渡すステージ済みファイルのみを対象にした。手動実行用の `pnpm run lint:fix`（リポジトリ全体）はそのまま残している
  - **未解決の背景要因**: `biome.json` は `"lineEnding": "lf"` だが、Windows 環境では `core.autocrlf=true`（`C:/Program Files/Git/etc/gitconfig` 由来）のため作業ツリーは CRLF になる。この不一致により、全体フォーマットを走らせると毎回すべてのファイルが「変更あり」と判定される。`.gitattributes` を追加して改行コードを明示するのが恒久対策だが、他の開発者にも影響するためチームでの合意が必要
